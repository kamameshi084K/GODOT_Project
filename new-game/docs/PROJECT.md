# プロジェクト状況

## 確定仕様

- Windows PC向け、Godotによる3D表示のブロックス。20×20の整数座標盤面を使い、UIは日本語。
- 青・黄・赤・緑の各21ピース、各色89マス。90度回転・反転を許可。配置確定後は移動不可。
- 初手は色ごとの固定開始角を覆う。以後は同色と角接触が必要で、同色の辺接触は禁止。異色同士の接触は自由。盤外・重複・使用済みは拒否。
- 手番は青→黄→赤→緑。合法手がない色はサーバーが自動パスし、任意パスは不可。4色とも配置不能なら終了。
- 4人では1人1色。2人では席1が青・赤、席2が黄・緑。3人では席1〜3が順に青・黄・赤を持ち、共有の緑は各緑手番に席1→2→3の順で操作する。緑の得点は個人得点に含めない。
- 色ごとの得点は未配置マス数の負数、全21ピース配置で15点、最後が1マスならさらに5点。2人では担当2色を合算。同点は同順位。
- 盤面・駒・照明・カメラは3D。手持ち、手番、プレビュー、理由、結果、ロビーなどは画面UI。カメラ回転後もマウス位置と盤面マスを一致させる。
- オンラインはENetのホスト兼サーバー方式。ホストを含め2〜4人、クライアント最大3人。サーバーだけが状態を確定し、RPC送信元・席・手番・合法性・match_id・state_revisionを検証する。確定状態を信頼性のあるRPCで同期する。
- 全員の画面準備後に開始。試合中の参加は不可。切断時は試合中止。通常終了後はロビーに戻って再戦可能。再戦は新しいmatch_idで初期化する。
- 初期版にアカウント、公開マッチング、ランキング、チャット、観戦、途中復帰、ホスト移行、CPU対戦は含めない。
- 正本はユーザー提供の詳細仕様と[Mattelのブロックス説明書](https://service.mattel.com/instruction_sheets/R1983%20-%20Blokus.pdf)。説明書の基本ルール、2人・3人の変則ルール、得点は提供仕様と一致する。ネットワーク仕様は採用Godot版の[公式文書](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html)に合わせる。

## 実装上の確定値と未決事項

- 開始角は青=(0,0)、黄=(19,0)、赤=(19,19)、緑=(0,19)とし、画面に表示する。座標は盤面を上から見たもの。
- 通信ポートは実装時に既定値を決め、画面で変更できるようにする。LANおよびインターネット越しのUDP接続条件を説明する。
- Godotは `C:\GodotEngine\Godot_v4.5.1-stable_win64_console.exe`。実行して `4.5.1.stable.official.f62fdbde1` を確認済み。GDScriptを採用する。
- 実機LAN、インターネット越しの接続は試験環境が必要。実施結果と未検証を分けて記録する。

## 段階と完成条件

1. **Phase 1: ルールと操作できる3D盤面**：21形状と89マス、配置・合法手探索、人数別担当、手番・自動パス・終了・得点を画面や通信と分離。単一PCでピース選択・回転・反転・プレビュー・配置を操作し、一局を終えられる。ルールの境界例を自動検証する。
2. **Phase 2: ホストとクライアントの接続**：部屋作成・参加、ロビー、画面準備同期を実装。別々のGodotプロセスから手を打ち、盤面・手番・revisionが一致する。
3. **Phase 3: 2〜4人対戦の完走**：各人数の席と色、共有緑、手番外・不正・重複・古い要求の拒否、終了結果、切断中止、再戦を確認する。
4. **Phase 4: 遊びやすさと実行手順**：日本語UI、カメラ、通信状態とエラー案内を整え、Windowsの起動・ビルド、LAN・インターネット越しの条件と検証結果を文書化する。

各段階の必要な検証・修正後、対象変更だけをローカルCommitする。Pushはユーザーが行う。

現在地：Phase 1のルール・3D盤面・ローカル操作と、Phase 2のENetロビー・画面準備同期・サーバー確定状態同期を実装。2人の別プロセス接続で4手の状態一致を確認。実画面での手操作は未確認。次はPhase 3の不正操作、2〜4人完走、切断、再戦の検証。
